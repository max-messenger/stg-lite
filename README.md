STG-Lite — мини-фреймворк для разработки небольших ботов в MAX. Это готовый механизм инициализации компонентов приложения: конфигурации, логгера, телеметрии, двух пулов подключений к Postgres, Redis, `HTTP`-роутера, основного и системного `HTTP`-серверов. Также в нём поддерживается корректное завершение работы сервисов (graceful shutdown)

Фреймворк позволяет:

- Настраивать приложение через YAML с использованием переменных окружения
- Вести структурированные логи с помощью zap
- Собирать и передавать трассировки через OTLP (`gRPC/HTTP`) с возможностью настройки выборки и передачи контекста между сервисами
- Работать с Postgres и Redis через готовые обёртки с OpenTelemetry-трейсингом и метриками Prometheus
- Управлять порядком завершения работы сервисов
- Запускать `HTTP`-сервер на базе Chi и системный сервер с эндпоинтами `/health`, `/metrics`, `/debug`
- Выполнять встроенные миграции через `SQL-migrate`


## 1. Структура проекта

Основные каталоги и файлы приложения:

| Путь | Назначение |
| --- | --- |
| `cmd/lite/main.go` | Точка входа в приложение: обработка флага `-c`, вызов `app.New` и `app.Run` |
| `internal/app/` | Инициализация приложения (`app.go`, `config.go`) и HTTP-роутер (`router/`) |
| `internal/info.go` | Переменные версии `CommitTag` и `CommitShortSHA`, значения которых передаются через `-ldflags` |
| `pkg/server/` | Основной HTTP-сервер (`:8080`) и системный сервер (`:23569`) с эндпоинтами `/health`, `/metrics`, `/debug` |
| `pkg/connections/postgres/` | Работа с Postgres через pgxpool и otelpgx; методы `Call` и `RunInTx` |
| `pkg/connections/rediscli/` | Универсальный клиент go-redis с поддержкой префиксов ключей |
| `pkg/telemetry/` | OTLP-трейсинг (gRPC/HTTP), сэмплер и propagator |
| `pkg/logger/` | Настройка zap-логгера из конфигурации |
| `pkg/grace/` | Управление завершением работы сервисов с учётом приоритетов |

| `config/lite/` | YAML-конфигурации приложения |

## 2. Запуск приложения

Последовательность инициализации компонентов определена в файле `internal/app/app.go`:

```text
config → logger → telemetry → Postgres (postgres-sel, postgres-upd) → Redis → chi-роутер → HTTP-сервер и системный сервер
```

При запуске создаются два пула подключений к Postgres: `postgres-sel` для чтения и `postgres-upd` для записи. Для каждого пула выполняется проверка доступности соединения (ping)

При каждом внешнем вызове автоматически собираются данные о выполнении операции (трассировки OpenTelemetry) и метрики Prometheus. Для формирования значения метки ошибки используется `telemetry.ErrLabelValue(err)`

## 3. Завершение работы приложения

За корректное завершение работы сервисов отвечает пакет `pkg/grace`. Сервисы регистрируются с приоритетами и останавливаются **в порядке возрастания их значений**. Сервисы с одинаковым приоритетом завершают работу параллельно

Используются следующие приоритеты:

1. `PriorityDefault` (`0`) — приоритет по умолчанию при регистрации через `graceful.Add`. Используется для основного HTTP-сервера и системного сервера
2. `PriorityLow` (`1`) — подключения к Postgres и Redis
3. `PriorityLowest` (`2`) — телеметрия

Порядок остановки компонентов в `internal/app/app.go`:

```text
HTTP-серверы (PriorityDefault) → Postgres и Redis (PriorityLow) → телеметрия (PriorityLowest)
```

Завершение работы запускается по сигналам `SIGINT` и `SIGTERM`. Таймаут составляет 15 секунд

## 4. Работа с Postgres

Для работы с Postgres используется пакет `pkg/connections/postgres` — обёртка над `pgxpool` с автоматическим сбором трассировок OpenTelemetry и метрик Prometheus для каждого вызова

В приложении предусмотрены два отдельных пула подключений:

- `pgSel` (`postgres-sel`) — подключение к репликам для выполнения запросов `SELECT`
- `pgUpd` (`postgres-upd`) — подключение к основному серверу для выполнения запросов `INSERT`, `UPDATE`, `DELETE` и транзакций

При работе с Postgres соблюдайте следующие правила:

- Не используйте `RawPool()` напрямую в бизнес-логике: такие запросы не будут сопровождаться трассировками и метриками
- Выполняйте запросы на чтение только через `pgSel.Call`. Использовать `pgUpd` для чтения запрещено
- Выполняйте запросы на изменение данных через `pgUpd.Call`, а транзакции — через `pgUpd.RunInTx`. Использовать `pgSel` для записи запрещено
- Если после записи необходимо сразу получить актуальные данные, выполняйте чтение в той же транзакции через `pgUpd`. Реплика может получать изменения с задержкой

### 4.1. Выполнение одного запроса

Для выполнения одного запроса используйте метод `Call`. В функцию обратного вызова передаётся подключение с типом `*pgx.Conn`

Пример запроса на получение имени пользователя:

```go
err := pgSel.Call(ctx, "get_user", func(ctx context.Context, conn *pgx.Conn) error {
    row := conn.QueryRow(ctx, "SELECT name FROM users WHERE id = $1", id)
    return row.Scan(&name)
})
```

### 4.2. Выполнение транзакций

Для выполнения нескольких запросов в одной транзакции используйте `RunInTx` только через `pgUpd`. При возникновении ошибки или паники (аварийного прерывания обычного выполнения кода в Go) транзакция откатывается

Пример:

```go
err := pgUpd.RunInTx(ctx, "create_order", func(ctx context.Context, conn *pgx.Conn) error {
    if _, err := conn.Exec(ctx, "INSERT INTO orders ..."); err != nil {
        return err
    }
    _, err := conn.Exec(ctx, "UPDATE stock ...")
    return err
}, pgx.TxOptions{})
```

Параметр `name` в методах `Call` и `RunInTx` задаёт имя операции в формате `snake_case`. Оно используется в метках метрик Prometheus и записях об отдельных операциях в трассировках OpenTelemetry

## 5. Работа с Redis

Для работы с Redis используется пакет `pkg/connections/rediscli` на основе универсального клиента go-redis. Он поддерживает префиксы ключей, сбор метрик и трассировок

Все операции с Redis выполняются через метод `Call`. Прямой доступ к клиенту не предусмотрен

### 5.1. Работа с ключами

Для каждого ключа внутри функции обратного вызова используйте `keyFormatter`. Он добавляет префикс экземпляра приложения. Без форматирования ключ будет передан в Redis без префикса

Пример получения сессии:

```go
err := rd.Call(ctx, "get_session", func(ctx context.Context, keyFormatter rediscli.FormatKey, ucl redis.UniversalClient) error {
    val, err := ucl.Get(ctx, keyFormatter("session:"+id)).Result()
    if errors.Is(err, redis.Nil) {
        return nil // ключа нет — не ошибка
    }
    return err
})
```

### 5.2. Выполнение нескольких команд

Внутри одного вызова `Call` можно выполнять несколько команд с разными ключами: клиент поддерживает конкурентное использование

Если требуется атомарное выполнение команд, используйте `ucl.TxPipeline()` внутри функции обратного вызова

Параметр `name` метода `Call` задаёт имя операции в формате `snake_case`. Это имя используется в метриках Prometheus и трассировках OpenTelemetry

## 6. Правила организации кода

При разработке приложения используйте следующие соглашения:

- **Импорт-префикс модуля** — `lite/...`, например `lite/pkg/server`
- **Структура пакетов** — размещайте компоненты с разным назначением в отдельных пакетах каталога `pkg/`. Обычно пакет содержит `config.go`, `metrics.go`, `options.go` и файл с основным типом
- **Функциональные опции** — используйте шаблон `Option func(*T)` и функции `WithX(...)`
- **Обработка ошибок** — добавляйте контекст через `fmt.Errorf("context: %w", err)`
- **Конструкторы** — используйте имена `New` или `NewXxx` и возвращаемые значения `(*T, error)`
- **Логирование** — используйте zap со структурированными полями. Для отдельных подсистем создавайте именованные логгеры через `.Named(...)`
- **Теги конфигурации** — записывайте YAML- и JSON-теги в формате `snake_case`. Соблюдение формата проверяет линтер `tagliatelle`
- **Загрузка конфигурации** — используйте `go.uber.org/config` с подстановкой переменных окружения в формате `${VAR:"default"}`

## 7. Проверка кода

Для проверки кода используется конфигурация `.golangci.yml`, в которой настроено около 50 линтеров, в том числе:

- `cyclop`
- `funlen` с ограничением в 150 строк и 50 инструкций
- `gocyclo` с максимальной цикломатической сложностью 20
- `lll` с ограничением длины строки в 140 символов
- `gosec`
- `revive`
- `nlreturn`
- `wsl`

Для форматирования используются `gofmt`, `goimports` и `gci`. В `gci` настроены секции `standard`, `default` и `localmodule`

Перед завершением работы выполните команду:

```bash
make lint
```
